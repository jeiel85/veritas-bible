## v1.8.2 — 뒤로가기 화면 뎁스 처리

### 핵심 변경

지금까지 앱에 `BackHandler` 가 전혀 없어, 어느 화면에서 뒤로가기를 누르든 곧바로 앱이 종료됐습니다. 각 화면 뎁스를 한 단계씩 거슬러 올라가도록 시스템 뒤로가기를 처리했습니다.

### 변경 사항

뒤로가기 우선순위(깊은 뎁스 → 얕은 뎁스):

- **연구 본문 직접-탭 모드**(`PassagePanel`): MARK/LINK 모드에서 뒤로가기 → 보류 중인 선택(`pendingFrom`) 취소 → READ 모드로 복귀.
- **연구 상세 화면**(`openSessionId != null`): 뒤로가기 → 연구 목록으로 복귀(바텀 네비 재노출).
- **리더 절 선택 활성**(`selectionAnchor != null`): 뒤로가기 → 선택만 해제.
- **비-리더 탭**(검색/연구/통계/노트/설정): 뒤로가기 → 성경읽기(READER) 탭으로.
- **리더 + 선택 없음**: 기본 동작(앱 종료).

다이얼로그(`AlertDialog`/`Dialog`)와 드롭다운(`DropdownMenu`)은 Compose 가 자체적으로 back 을 dismiss 로 처리하므로 별도 핸들러를 두지 않았습니다. `BackHandler` 의 `enabled` 플래그가 상호 배타적이라 각 뎁스에서 정확히 하나의 핸들러만 활성화됩니다.

### 구현

- `MainActivity.WordStudyAppMain`: 상세-닫기, 탭→리더 두 개의 `BackHandler`.
- `BibleReaderScreen`: 선택 해제 `BackHandler`.
- `StudyDetailScreen.PassagePanel`: 탭 모드 단계 취소 `BackHandler`.

### 데이터 안정성

- 데이터베이스 스키마 변경 없음 (Room v6 유지, 마이그레이션 없음). 기존 마킹·연결·메모·연구 세션은 모두 그대로 보존됩니다.
